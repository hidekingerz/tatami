# レイアウトセット 実機確認の手順

ブランチ feature/layout-sets をビルドして行う。署名が変わっていればアクセシビリティ権限を取り直す。

## A. スパイク（デバッグメニュー、Task 2）


```bash
defaults write dev.hidekingerz.tatami debugMenu -bool YES
# Xcode でビルドして Tatami.app を起動（署名が変わっていればアクセシビリティ権限を取り直す）
log stream --predicate 'subsystem == "dev.hidekingerz.tatami" AND category == "Debug"' --level debug
```

システム設定 → キーボード → キーボードショートカット → Mission Control で「デスクトップ 1〜3 へ切り替え」をオンにしておく。
システム設定 → デスクトップと Dock → Mission Control の「最新の使用状況に基づいて…」は、この確認の間だけオフにする（番号を安定させるため）。

WezTerm は `window_decorations` の設定値も報告してもらう（`RESIZE` だとタイトルバーがなく掴めない）。

メニューバーの tatami → 「デバッグ」に項目が出る。ログの「候補点=」は 0 始まり（0=(a) 信号機の右、1=(b) 中央、2=(c) 右端、3=(d) 上端の帯。幅 200 未満の窓では 0=(b)、1=(d)）。

## B. 配線・HUD（Task 9）

1 セットを仕込む（設定画面はまだ無いので defaults で。WezTerm を左半分・Chrome を右半分にする例。アプリを起動していない状態で実行し、その後 tatami を起動する）:

```bash
json='[{"id":"6F1C2B9E-0000-4000-8000-000000000001","name":"作業","rows":[{"id":"6F1C2B9E-0000-4000-8000-000000000011","bundleIdentifier":"com.github.wez.wezterm","appName":"WezTerm","titleFilter":"","action":"leftHalf"},{"id":"6F1C2B9E-0000-4000-8000-000000000012","bundleIdentifier":"com.google.Chrome","appName":"Google Chrome","titleFilter":"","action":"rightHalf"}]}]'
defaults write dev.hidekingerz.tatami layoutSets.v1 -data "$(printf '%s' "$json" | xxd -p | tr -d '\n')"
```

1. メニューに「レイアウトセット…」と「作業」が出る。
2. 「作業」を選ぶと「作業 を適用中…」の HUD が出たあと WezTerm と Chrome が並び、HUD が「作業: 2 件を配置」に変わって 2 秒で消える。消える前に HUD をクリックすると即閉じる。
3. Chrome を終了して再び選ぶと「作業: 2 件中 1 件を配置 ・ Google Chrome は起動していません」。文が長いぶん表示が少し長い。
4. 設定画面を前面にして ⌃⌥b を押すと beep し、設定画面は動かない。閉じれば従来どおり。
5. フルスクリーンにした Chrome の上で「作業」を適用すると、HUD はその空間の上に出て、空間を離れない。Chrome の行は「Google Chrome はフルスクリーンです」。

## C. ピッカー（Task 10）

ピッカーのホットキーを試すには、アプリを終了した状態で例えば
`defaults write dev.hidekingerz.tatami KeyboardShortcuts_layoutSets.picker -string '{"carbonKeyCode":35,"carbonModifiers":6144}'`
（⌃⌥P の例。carbonModifiers: control=4096, option=2048, cmd=256, shift=512。bundle id は実際のものに合わせる）を書いて起動する。
もしくはメニューの「レイアウトセット…」から開く（ホットキーなしで 1〜7, 10 は確認可能）。セットは Task 9 までの経路（キャプチャ等）か UserDefaults `layoutSets.v1` で用意する。

1. ピッカーが画面中央上寄りに出て、検索欄にフォーカスがある。
2. ↑↓ で選択が動き、端で止まる。文字を入れると絞られ、選択が先頭に戻る。
3. → で内訳が開き、← で閉じる。
4. Enter またはクリックでピッカーが閉じ、セットが適用され、HUD が出る。
5. esc で閉じる。別のアプリをクリックしても閉じる。
6. 別のデスクトップでもピッカーが出る。フルスクリーンアプリの上でも出て、その空間を離れない。
7. ⌘⏎ で設定画面が開く（Task 11 まではタブは既定のまま）。案 A（メニューを一度開いた後）と案 B（起動直後、メニュー未表示）のどちらで動いたかを記録し、動かない方を消す。
8. 適用中（HUD が「適用中…」の間）にピッカーのキーを押すと beep して開かない。
9. ピッカーを esc で閉じた直後に ⌃⌥m を押すと、ピッカーを開く前に前面だったアプリの窓が最大化される（beep しない）。
10. 検索欄に文字を入れた状態でも ↑↓ / ⏎ / esc が効く。
11. ピッカーを開いた状態で別アプリをクリック → そのアプリがフォーカスを保ち、元のアプリに戻らない。
12. 検索欄で日本語入力の変換中に ⏎ / ↑↓ / esc → 変換の操作になり、ピッカーの適用・選択・閉じるが起きない。

## D. 設定「セット」タブ（Task 11）

`defaults delete dev.hidekingerz.tatami` で設定を消した状態から始める。
1. 設定に「セット」タブがあり、ウィンドウ幅 640 で既存タブも崩れない。
2. 「ピッカーを開く」にキーを記録し、どのアプリの前面でもピッカーが出る。
3. 「セットを追加」→ 名前を「作業」にし、行を 2 つ（WezTerm `herdr` を左 2/3、Chrome を右 1/3）作ってキーを記録 → そのキーですぐ適用される。
4. 自動並べ替えがオンのまま行にデスクトップ 3 を入れると警告が出る。「オフにする…」→ 確認 → Dock が再起動し、警告が消える。
5. デスクトップ 3 のショートカットがオフだと警告が出る。「システム設定を開く」でキーボードショートカットの画面が開く。オンにして設定画面に戻ると警告が消える。
6. 「連絡」セット（LINE / Discord / Teams を 1/3 ずつ、デスクトップ 3）で、LINE をデスクトップ 1 に置いた状態から適用 → LINE がデスクトップ 3 へ移り、3 枚が並ぶ。HUD に「連絡: 3 件を配置」。
7. Teams を終了して適用 → 「連絡: 3 件中 2 件を配置 ・ Microsoft Teams は起動していません」。
8. 「いまの配置を保存」→ デスクトップ「指定しない」→ 見えている窓の数だけ行ができる。左 2/3・右 1/3 に置いた窓はその区画になり、自由なサイズの窓は「何もしない」になる。同じアプリの窓が 2 枚あれば絞り込みは空のままで、「同じアプリが複数あります」の注意が出る。
9. 行のドラッグでの並べ替え、削除、「変えない」の選択が保存され、再起動後も残る（Form 内の onMove が効くかをここで確かめる）。
10. セットを削除するとそのキーが効かなくなり、再起動後も戻らない。
11. ピッカーで ⌘⏎ → 設定の「セット」タブが、そのセットを開いた状態で出る。
12. 既存の 8 ショートカットが変更前と同じように動く（設定ウィンドウを閉じたあとに beep しないことも確かめる）。

## E ピッカーからの区画適用

仕様: `docs/superpowers/specs/2026-11-02-picker-regions-design.md` §8。ブランチ feature/picker-regions をビルドして行う。

- [ ] 別アプリを前面にしてホットキーでピッカーを開き、`r3` ⏎ でそのアプリの窓が右 1/3 になる。
- [ ] 日本語入力のまま開いて `left` と打てる（ABC に切り替わる。最初の 1 文字が IME に取られないか）。
  閉じると日本語入力に戻る（esc、適用、別アプリをクリック、⌘⏎ の 4 経路）。
  「書類ごとに入力ソースを切り替える」がオンの環境でも、前のアプリに戻ったあとの入力ソースが開く前と同じか。
- [ ] 元から ABC のとき、閉じても入力ソースが変わらない。
- [ ] ピッカーを開いたまま tatami を終了したとき、入力ソースが元に戻るか。戻らなければ `applicationWillTerminate` で `restore()` を呼ぶ。
- [ ] ⌘D と ★ クリックで付け外しでき、再起動後も先頭に出る。設定画面の ★ と同期している。
- [ ] 窓のないアプリ（Finder でデスクトップだけ）を前面にして開き、区画を ⏎ すると HUD「対象のウィンドウがありません」が出る。
- [ ] ピッカーを開いた後に対象の窓を閉じてから ⏎ すると HUD「ウィンドウを動かせませんでした」が出る。
- [ ] ピッカーから区画を適用した直後に ⌃⌥b を押すと、左半分→左 1/3 のループが「次」から続く。
- [ ] 設定画面を開いたままピッカーを出して区画を ⏎ すると、設定画面は動かず HUD「対象のウィンドウがありません」が出る。
- [ ] 区画の行の ★ をクリックすると ★ だけが切り替わり、区画は適用されない（ピッカーが閉じない）
- [ ] 検索欄にフォーカスがある状態で ⌘D を押すと ★ が切り替わる（beep しない、メインメニューに取られない）。そのあと `d` を打つと検索欄に入る
- [ ] ★ の付け外しで一覧の順序が変わるとき、パネルの上端は動かず高さだけ変わる
- [ ] フルキーボードアクセスがオンでも、Tab で ★ ボタンにフォーカスが移って検索欄から外れない
- [ ] メニューバーの「ピッカー…」から開いたときも、直前に前面だったアプリの窓に区画が適用される
- [ ] 区画の行で ⌘⏎ すると、その区画のカテゴリのタブで設定画面が開く（左半分・右半分は「半分」タブ）
- [ ] ⌘D で ★ を付け外ししたあと、選択のハイライトがその区画に付いてくる
- [ ] 「tatami を終了」をピッカーが開いたまま実行しても、入力ソースが元に戻る
